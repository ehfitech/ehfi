# EHFI PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make EHFI installable from supported browsers and launch from a home-screen or desktop icon in standalone mode.

**Architecture:** Use the Next.js 16 App Router's built-in `app/manifest.ts` convention and root layout metadata. A small client-side sync inside the existing theme provider updates browser theme-color metadata from the active CSS background token. Do not add a service worker or PWA dependency; installation metadata is independent of offline and push features.

**Tech Stack:** Next.js 16.4.3 App Router, TypeScript, existing static assets under `public/`.

**Spec:** `docs/superpowers/specs/2026-10-30-ehfi-pwa-design.md`

## Global Constraints

- No new dependencies.
- Do not add Web Push, notifications, VAPID configuration, service worker, custom offline behavior, a database, or an install button.
- Do not resize or convert the user's icons. Reference their final PNGs at the exact paths in the spec.
- Do not run or add tests, lint, type checking, or builds.
- Do not run `git` or deploy the app.

## Review Focus

- The App Router manifest is available at `/manifest.webmanifest` and linked by Next automatically.
- `display`, `start_url`, and `scope` keep installed EHFI routes in a standalone window.
- Chromium's required 192×192 and 512×512 images must exist at the specified URLs before mobile installability is complete.
- iOS receives the Apple touch icon and Apple standalone metadata.
- No active light or dark theme leaves the status bar set to the pink accent color.
- Localhost is for same-device development; phone testing through a LAN IP requires HTTPS.
